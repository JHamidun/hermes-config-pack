# Конфиг-пак для Hermes Agent

Обезличенный набор рабочей среды агента: **424 навыка**, каждый — слэш-команда,
**74 роли** для делегирования, **29 CLI-инструментов** на Python (почта, диск,
календарь, мессенджеры, парсинг, медиа, дизайн) и хук, который не даёт агенту
выполнить разрушительную команду.

Это порт [конфиг-пака Claude Code](https://github.com/JHamidun/claude-code-config-pack)
на Hermes. Исходник тот же, переносом занимается конвертер — что именно
изменилось и почему, написано в [PORTING.md](PORTING.md).

## Быстрый старт

```bash
git clone https://github.com/JHamidun/hermes-config-pack.git
cd hermes-config-pack
python install.py
hermes plugins enable ccpack
hermes ccpack install
hermes ccpack doctor
```

Подробно, включая три шага, которые делаются руками — [INSTALL.md](INSTALL.md).

## Или поштучно, без установки целиком

Репозиторий работает и как источник навыков: `skills/` лежит в корне, а это то,
что Hermes ждёт от tap.

```bash
hermes skills tap add JHamidun/hermes-config-pack
hermes skills inspect JHamidun/hermes-config-pack/skills/pdf
hermes skills install JHamidun/hermes-config-pack/skills/pdf
```

Три вещи, которые лучше знать заранее — проверено на живом Hermes 0.21.3:

* **Ищи по полному имени, а не через `hermes skills search`.** Перечисление tap
  опрашивает GitHub по каталогу на навык; на 413 навыках это упирается в лимит
  API (без токена — 60 запросов в час), и навыки просто не доезжают до выдачи.
  `inspect` и `install` по полному идентификатору работают сразу. Список имён —
  в [CATALOG.md](CATALOG.md).
* **Часть навыков потребует `--force`.** Hermes прогоняет навыки из хаба
  собственным сканером, и он считает высоким риском `sudo apt-get` и `pip
  install` без версии — а это ровно то, что написано в инструкциях по установке
  зависимостей. Посмотри находки глазами и решай сам; при установке паком
  целиком этот путь не используется.
* **Приедет только `SKILL.md` и файлы самого навыка.** Ни ролей, ни CLI из
  `tools/`, ни гарда — они живут в плагине. Навык, который зовёт скрипт пака,
  честно скажет, что его нет.

## Что внутри

| Каталог | Что это |
|---|---|
| `skills/<категория>/<имя>/` | навыки: 24 категории; каждый вызывается `/<имя>` |
| `agents/<имя>/` | роли для `delegate_task`, грузятся `skill_view("ccpack:<имя>")` |
| `tools/*.py` | самостоятельные CLI: Telegram, Gmail, Google Drive/Calendar, IMAP, Figma, Miro, OSINT, вебхуки, SMS, Home Assistant |
| `scripts/*.py` | служебные: линт конфига, проверка ссылок, память, санитайз |
| `config/*.md` | справочники: модели, роутинг, MCP-серверы |
| `rules/*.md` | правила поведения целиком |
| `templates/` | четыре файла, которые заполняешь собой |
| `hooks/ccpack-guard.js` | гард деструктивных команд (нужен node) |
| `AGENTS.md` | инструкции проекта: где что лежит и как называется |
| `SOUL.example.md` | заготовка личности агента |
| `config.snippet.yaml` | что дописать в `config.yaml` |

`/ccpack find <слово>` ищет навык, `/ccpack roles` показывает роли,
`/ccpack status` — что подключено.

## Чем это отличается от версии для Claude Code

Коротко: **команды стали навыками** (у Hermes каждый навык и так слэш-команда),
**агенты стали ролями** (именованного реестра субагентов нет — есть
`delegate_task` плюс `skill_view`), **пути переехали** с `~/.claude` на
`~/.hermes/ccpack`, **ключи** читаются из `$HERMES_HOME/.env`, **описания
навыков** ужаты под 60-символьный индекс Hermes, а полный текст с триггерами
переехал в тело навыка. Таблица соответствий инструментов и подробности —
[PORTING.md](PORTING.md).

## Требования

Hermes Agent 0.21+, Python 3.11+ (для CLI), node (только для гарда).
Ключи не обязательны: всё, что не ходит наружу, работает и без них.
