# Перенос конфиг-пака Claude Code на Hermes

Что пришлось изменить, почему, и что сознательно осталось несовершенным.
Написано для того, кто будет вести этот пакет дальше — после следующего
обновления клод-пака.

## Почему это не копирование

Форматы навыков совпадают: и Claude Code, и Hermes читают `SKILL.md` с
фронтматтером по стандарту agentskills.io. Из-за этого кажется, что достаточно
скопировать каталог. Замер говорит иначе:

* **1185 ссылок на `~/.claude`** в 380 файлах — пути личного конфига, которых у
  пользователя Hermes нет. В скриптах это не текст, а живой
  `load_dotenv(Path.home() / ".claude" / ...)`, который **молча** не найдёт файл;
* **156 слэш-команд** — у Hermes нет markdown-слоя команд вообще;
* **74 агента** — у Hermes нет реестра именованных субагентов;
* **категория навыка задаётся каталогом** (`skills/<категория>/<имя>/SKILL.md`), а
  в паке 315 навыков лежат плоско;
* **description режется на 60 символах** в индексе системного промпта, а у пака
  медиана 145.

Встроенный `hermes import-agent claude-code` закрывает первый и последний пункты
частично, а `commands/` пропускает с припиской «convert them into skills» и
`agents/` не умеет вовсе. Поэтому — конвертер.

## Шесть решений, на которых стоит порт

### 1. Команды → навыки

В Hermes **каждый установленный навык автоматически становится слэш-командой**, а
текст, написанный в том же сообщении, приходит агенту как инструкция — ровно
семантика `$ARGUMENTS`. Поэтому `commands/deep-research.md` стал
`skills/<категория>/deep-research/SKILL.md` и вызывается `/deep-research <запрос>`.
В начало каждого такого навыка добавлен абзац о том, откуда берутся аргументы.

Плагинные слэш-команды (`ctx.register_command`) — не тот инструмент: их
возвращаемое значение **печатается пользователю**, а команда пака должна отдать
процедуру **модели**. `/ccpack` — плагинная команда именно потому, что она и
должна печатать.

### 2. Агенты → роли + `delegate_task`

У Hermes нет `subagent_type`. `delegate_task` порождает ребёнка с пустым
контекстом и тулсетами родителя. Каждый `agents/*.md` стал
`agents/<имя>/SKILL.md` и регистрируется плагином через `ctx.register_skill`, то
есть доступен только по явному `skill_view("ccpack:<имя>")` и **не попадает в
системный промпт**: 74 роли не стоят ничего, пока не понадобятся.

Потерялось при переносе:

* **ограничение инструментов на агента.** `tools:` во фронтматтере Claude сужал
  агента до белого списка; ребёнок в Hermes наследует тулсеты родителя, и
  `delegate_task` не принимает список инструментов. Теперь это записано в роли
  как указание, а не как ограничение;
* **модель на агента.** `model: fable` выбирал агенту модель; в Hermes ребёнок
  берёт модель из `delegation.model`. Исходное значение сохранено в роли как
  `suggested_model`.

### 3. Имена инструментов

| Claude Code | Hermes |
|---|---|
| `Read` | `read_file` |
| `Write` | `write_file` |
| `Edit`, `MultiEdit`, `NotebookEdit` | `patch` |
| `Bash` | `terminal` (и `process` для фоновых) |
| `Glob`, `Grep` | `search_files` |
| `Task` | `delegate_task` |
| `TodoWrite` | `todo` |
| `AskUserQuestion` | `clarify` |
| `WebFetch`, `WebSearch` | `web_extract`, `web_search` |
| `SlashCommand`, `Skill` | `skill_view` |
| `mcp__сервер__инструмент` | `mcp_сервер_инструмент` |

Замена **текстовая**, и в этом её слабость: «read», «write», «task» — обычные
английские слова, встречающиеся в этих навыках на каждой странице. Поэтому
восемь двусмысленных имён (`Read`, `Write`, `Edit`, `Bash`, `Glob`, `Grep`,
`Task`, `Skill`) переписываются только в однозначной позиции — в обратных
кавычках, перед скобкой вызова, в списке инструментов. Остальные — везде.

### 4. Пути

| Claude Code | Hermes |
|---|---|
| `~/.claude/tools/`, `scripts/`, `config/`, `rules/`, `templates/` | `~/.hermes/ccpack/<то же>` |
| `~/.claude/skills/<имя>/` | `~/.hermes/skills/<категория>/<имя>/` |
| `~/.claude/.credentials.master.env` | `$HERMES_HOME/.env` |
| `~/.claude/projects/<проект>/memory/` | `~/.hermes/memories/` |
| `~/.claude/projects/` (транскрипты) | `~/.hermes/sessions/` |
| `~/.claude/CLAUDE.md` | `~/.hermes/ccpack/AGENTS.md` |
| `~/.claude/settings.json`, `~/.claude.json` | `~/.hermes/config.yaml` |

Пути пишутся **буквально**, а не через `$CCPACK_HOME`: навык, поставленный через
tap, не имеет плагина, который экспортировал бы переменную, а команда с
неустановленной переменной ломается молча и в худшую сторону. Переменная всё
равно уважается — внутри python-скриптов, где резолвинг наш.

Дом пака — `~/.hermes/ccpack` на любой ОС. Это **не** дом рантайма: на Windows
Hermes живёт в `%LOCALAPPDATA%\hermes`. Поэтому `$HERMES_HOME/.env` в текстах
написан переменной, а в python-скриптах резолвится тем же правилом, что и в
самом рантайме (`HERMES_HOME` → платформенный дефолт).

### 5. Описания навыков

`agent/skill_utils.py::SKILL_PROMPT_DESC_LIMIT = 60` — длиннее описание в индексе
обрезается многоточием. У пака описания устроены иначе: «что делает + Триггеры:
… + НЕ … → другой навык», медиана 145 символов, максимум 618.

Конвертер берёт первое предложение до «Триггеры», ужимает до 60 по границе слова
— и **кладёт полный исходный текст в тело навыка** под заголовком «Когда
применять». Так в индексе остаётся читаемая строка, а триггеры и маршрутные
подсказки не теряются: `skill_view` показывает их целиком.

Для сравнения: у штатных навыков Hermes медиана описания 57 символов, но и они
выходят за лимит там, где это оправдано (до 517). То есть 60 — норма стиля, а не
жёсткая проверка.

### 6. Хук-гард

Контракт shell-хуков Hermes **совместим с Claude Code**: тот же JSON на stdin
(`tool_name`, `tool_input`), тот же `exit 2 = блок`, принимаются обе формы ответа
(`decision/reason` и `action/message`). Поэтому 800 строк разбора команд не
переписывались: гард перенесён пятью точечными патчами —

* имена инструментов Hermes отображаются в те, которые ждут обе ветки гарда;
* `tool_input.path` принимается наряду с `file_path`;
* лог блокировок уехал в `~/.hermes/ccpack/hooks-logs/`;
* в список личных путей добавлен `.hermes`;
* текст блокировки назван по паку.

Каждый патч привязан к якорю в исходнике, и **отсутствие якоря валит сборку**:
иначе обновление гарда сверху молча дало бы файл, который всё пропускает.
Оригиналы лежат рядом в `hooks/upstream/` — для диффа против следующей версии.

## Что не переносится и почему

* **`settings.json` целиком.** Пак работает в `bypassPermissions` с бланкетным
  `Bash(*)` в allow, а барьером служат deny-список и хук. Выкатывать такую
  посадку в чужой Hermes нельзя, поэтому `config.snippet.yaml` содержит хук и
  подключение навыков, а режим одобрений остаётся тот, который выбрал сам
  пользователь.
* **Плагины Claude Code** (33 штуки маркетплейса). Плагин Hermes — это
  python-пакет с `register(ctx)`, а не markdown-набор. Навыки из этих плагинов
  дублируют то, что уже лежит в `skills/`.
* **`rules/` как авто-загрузка.** Claude Code читает все правила каждую сессию;
  у Hermes такого механизма нет — есть `SOUL.md` (личность) и один проектный
  контекст-файл. Поведенческое ядро пересказано в `AGENTS.md`, полные тексты
  остались в `rules/` и читаются по требованию.
* **GSD.** Подкаталог `commands/gsd/` пропущен: он уже перенесён отдельным
  пакетом (`gsd-hermes`), и вторая расходящаяся копия хуже, чем её отсутствие.

## Известные ограничения

**Вложенные навыки.** У пака 32 `SKILL.md` внутри других навыков. Те, что лежат
в `references/`, `templates/`, `assets/`, `scripts/`, Hermes не видит вовсе
(`is_skill_support_path`) — это справочный материал, и он так и оставлен. Прочие
11 (`gstack/browse`, `gstack/qa`, …) рантайм видит и зарегистрировал бы под
голыми именами `/browse`, `/qa`, `/ship`. Им проставлено имя с префиксом
родителя, потому что Hermes берёт имя из фронтматтера, а не из каталога — файл
остался на месте, относительные ссылки целы.

**Коллизии имён со штатными навыками Hermes.** Часть имён пака совпадает с тем,
что Hermes ставит сам (`design-orchestrator`, `moodboard`, `wireframe`,
`security-audit`, `git-workflow`, …). Побеждает тот, кого рантайм просканирует
позже. `hermes ccpack install` печатает список совпадений — переименовывать надо
осознанно, поштучно.

**MCP-серверы.** Имена переписаны в гермесовскую схему, но сами серверы надо
объявить в `config.yaml` (`mcp_servers`) и дать им ключи. Пока сервер не
объявлен, навык, который его зовёт, честно скажет, что инструмента нет.

**Навыки, которым нужен сам Claude CLI.** 47 навыков вызывают `claude -p`. Они
перенесены как есть: это внешняя программа, и если она стоит — они работают.

**Текстовая замена остаётся текстовой.** Линт (`tools/lint_package.py`) проверяет
ноль остатков `~/.claude`, ноль claude-имён инструментов в тулозициях, уникальность
слэш-имён и наличие каждого файла, на который ссылается текст. Но новая формулировка
в следующем релизе пака может лечь мимо всех правил — поэтому после каждой
пересборки смотрят дифф, а не только выхлоп линта.

## Пересборка после обновления клод-пака

```bash
python tools/sync_source.py     # обновить _source/ из ccpack-mp
python tools/convert.py         # пересобрать build/ccpack (идемпотентно)
python tools/make_config.py     # AGENTS.md, SOUL.example.md, config.snippet.yaml
python tools/lint_package.py    # приёмка: 0 ошибок — обязательное условие
git diff --stat                 # смотреть, что реально изменилось
```

Конвертер детерминирован и пересобирает `build/ccpack` с нуля каждый раз.
Ручная правка внутри `build/` будет затёрта — правится либо исходный пак, либо
правило в `tools/rewrite.py`.
